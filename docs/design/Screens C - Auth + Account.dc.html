foerier SCREENS C — AUTH + ACCOUNT
Passkeys only, invites out of band, auth on exactly two surfaces: the signed-out shell and the Account tab. Frames reuse the Screens A/B shells; new atoms live on the component sheet §09. Sample household: Veldkamp — Mark · Els · Kees (child, joins trips, never signs in).
00 — GROUND RULES (VISIBLE IN EVERY FRAME BELOW)
NO PASSWORDS
No password field, no “forgot password”, no email. foerier sends no mail.
NO USERNAMES
Sign-in is one button. The passkey already knows who you are.
FALLBACK IS FIRST-CLASS
A device without a passkey is an equal. No warning colors, no “degraded” copy.
QUARTERMASTERS ARE EQUAL
No owner, no admin, no crowns, no ordering by privilege. Anywhere.
OFFLINE WORK SURVIVES AUTH
Every screen where a session ends states that on-device work is kept.
INVITES: SINGLE-USE, EXPIRING
Always stated, with the remaining time: 6 d for a join invite, 58 min for a device link.
OPENING A LINK DOES NOTHING
The confirm button is the action. The join screen says so in plain words.
TWO SURFACES ONLY
Signed-out shell + Account. Never a re-auth prompt or banner inside Depot, Trips, Find.

RESUMABLE, AND NOT AN ERROR
The bootstrap cursor is persisted per page, so a dropped connection pauses the fold and continues it — it never restarts. Nothing is wrong with the user’s world, so nothing reads as an error: the header dot is the only amber, there is no ▲, the bar keeps its colour and its progress, and RETRY NOW is a quiet text action beside the fact line.
