DOMAIN RIGOR
Depot shows no packing status — that belongs to a trip. Home world shows HOME path + whereabouts only. Gear on a trip keeps its home path (muted) and gains the amber ▸ trip marker. DECISIONS ON THIS SCREEN
A screen, not a sheet — confirmed against the sheet alternative, not inherited: the OS keyboard owns the lower half for a whole sitting, the Home picker stacks on top as the only sheet, and Split renders the same form in the detail pane.
Order = the ledger line being written: NAME · KIND (+ count) · HOME · RECORDED AS. Container moved from slot 2 — an implementation accident — to last: the rarest decision and the only irreversible one sits where the eye lands before committing. The checkbox is retired; the trait is RECORDED AS · ITEM | CONTAINER, the glossary’s own meta-line words, with permanence stated: FIXED WHEN RECORDED. A checkbox reads as a setting; this is not a setting.
After Add the screen stays. Name clears and keeps focus, Kind / count / trait reset to defaults, HOME CARRIES OVER within the sitting — a depot is recorded shelf by shelf; a fresh entry starts at Loose. The confirmation line under the title carries UNDO (restores the record into the form, removes the op) and opens the record’s detail on tap. Round 1’s navigate-to-detail after every record is retired.
Return key records: type name → return → type the next name. The two-action record; the keyboard never dismisses. The CTA gates on Name — and on Owned count when Counted: the well opens empty and waits, because a silent ×1 is a wrong ledger line.
STATES COVERED
Fresh open: defaults SINGLE + ITEM + Loose, empty focused Name, disabled CTA (393) · mid-sitting: session count, confirmation + UNDO, home carried, keyboard up — RECORDED AS and the CTA sit under it; the batch loop never needs them (393) · Counted reveal below Kind + empty gated count well (540, 448 measure) · the container case in the Split pane, list kept (900). Entry points stay §2’s + Add gear and §3’s FAB. Owned count still inserts BELOW Kind — nothing at or above the thumb moves.

DECISIONS ON THIS SHEET
Two jobs, one sheet, two modes. Picking is the whole fast path: every row is a bare tap target — one tap selects and closes. RENAME / REMOVE moved off the pick rows into an EDIT mode (quiet mono toggle, top right): round 1 laid both jobs on every row because the build had, and a 12-place household’s picker was a wall of controls around a one-tap task. Creation stays in the pick path — + NEW PLACE is how a new shelf enters mid-sitting, and a place created while picking is selected immediately.
Current home is marked ● NOW (the SET PHASE anatomy) — round 1 didn’t mark it; MOVE without it can’t show where the gear stands. Loose stays first, two-line: the picker is where the glossary word LOOSE is taught.
Nesting: indent 16px per level, capped at TWO levels below the Place (was three); deeper rows keep the cap indent and carry their skipped ancestry as a meta line under the name — the GearRow name+meta anatomy — replacing round 1’s inline parent prefix, which fought the name scan.
RULES THAT HOLD
Plain gear is never offered; the moved gear and its whole subtree are absent at any depth (invariant 3) — one footer line says so in MOVE. REMOVE always confronts the loose-count first (invariant 4). Rename on Places only — containers are gear, renamed from their own EDIT. Selection closes the sheet; rename, remove and create do not. Row names are sentence-case (⌂ Attic); mono caps ⌂ ATTIC stays the path / label register. Shared by Add Gear and MOVE — the caller supplies only the exclusion and the context line.
