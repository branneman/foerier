# Handoff: Foerier — Quartermaster's tool (design system + core screens)

## Overview
Foerier is a household gear ledger for families who camp/trek: a **Depot** (where every piece of gear lives at home), **Trips** (gear lists, pack-out, unpack), and **Find** (offline "where is it?"). Dark theme is the default. This bundle contains the visual foundations, user flows, component sheet, seven core screens, and the full auth & account surface (Screens C).

## About the Design Files
The `.dc.html` files in this bundle are **design references created in HTML** — prototypes showing intended look and behavior, not production code to copy directly. Recreate these designs in the target codebase's existing environment (React, Vue, SwiftUI, native, …) using its established patterns and libraries. If no environment exists yet, choose the most appropriate stack (this is an offline-first mobile-primary app; local-first storage with background sync is a core requirement) and implement the designs there. Open each file in a browser to view it (`support.js` must sit next to them).

## Fidelity
**High-fidelity.** Colors, typography, spacing, and copy are final; recreate pixel-perfectly. The boards also contain annotation cards ("DECISIONS ON THIS SCREEN") beside each phone frame — these are rationale for the developer, not UI. The screens themselves are the framed artboards — 393px (Compact/Comfortable), 540px (Roomy), 900px (Split), 1024px (Desktop) — each marked with `data-screen-label`.

**Scope: the LATER tag.** Elements carrying the quiet mono `LATER` tag (dashed border, ink/faint — spec in Components §10) are drawn final and **decided, but not MVP**: the ledger group on Gear detail (story 33), all weight totals (story 16), `SAVED SLICES` in the Depot sidebar (story 34), and the whole Depot bulk bar (story 35). Build the MVP without them; their design does not change when they land. Two same-anatomy text variants: a **slice number** (`S9` on Find's per-person card — restaged from `S8 · PIECES` at the S8 round, §5d I) marks an MVP element that lands with a later slice — decided, not Later; **`API FIELD`** marks copy blocked on an endpoint field (the join-flow person names) — omitted until the field exists, never faked. Where a LATER element is a segment of a composite line (builder header/footer, gear meta), the MVP variant is drawn alongside. Everything untagged is MVP.

**This file has two writers, and regenerating it drops one of them.** The boards write the anatomy, copy and measurements. The **code** writes back everything recording what a slice actually did with a drawn decision — marked by a slice tag (`(S3)`, `(S3.5)`), by `retired`, by `drawn but not built`, by `landed in …` with a commit SHA, or by `redrawn round N`. They are concentrated in §2, §3a, §3b, §3c, §4a, §9 and §10, and there are enough of them that losing the set is not a small edit. A board redrawn from an older snapshot cannot know about any of them, so a regenerated README silently reverts them — and a reverted annotation reads as a *decision*, not as a loss.

So: **the repo copy at `docs/design/README.md` is authoritative, and a design round starts by re-seeding from it.** Preserve every code-authored annotation verbatim through a regeneration; never drop one because the current boards do not explain it — that is exactly the annotation worth keeping. If a board change genuinely contradicts one, say so as a conflict rather than resolving it silently: the code may need to change, or the board may be rediscovering something already settled. And **diff this file before committing a drop** — that is the net that catches whatever the re-seed missed.

### Spacing & grid
- Base **4px**; steps 4 · 8 · 12 · 16 · 20 · 24 · 32. Gutter by mode: 12 Compact · 16 Comfortable · 20–24 Roomy · 24 Split/Desktop. Content max-width 1120px, centred past 1200.
- Stack rhythm: gap ≈ 0.5–0.75 × the **next** element's line-height, snapped to 4 (20 before a title, 12 before a heading, 8 before body, 4 for tight text+meta pairs). Between cards 8–12; between sections 24–32.
- List row anatomy: side padding 16, vertical padding 12, title→meta gap 4. Two-line row = 70px; one-line min 56; packing rows ≥64. Whole row is the tap target.

### Responsive (five layout modes)
Shell breakpoints are **em-based media queries** (they track user font-size and zoom). Component internals adapt via **container queries** to the width they're handed — the same row/card renders 1-up or folded depending on its pane, not the viewport; no `@container` support fails open to single column.
| Mode | Range | Nav | Panes |
|---|---|---|---|
| Compact | <30em (<480) | Bottom tabs | Single column |
| Comfortable | 30–40em (480–640) | Bottom tabs | Single column |
| Roomy | 40–52em (640–832) | Bottom tabs | Single column, capped measure; cards 2-up, chips wrap, rows gain inline meta |
| Split | 52–64em (832–1024) | Icon rail (56px) | List + detail two-pane |
| Desktop | ≥64em (≥1024) | Labeled sidebar (216px) | Two/three-pane; centres at max-width 1120 past 75em (1200) |

**Built — the shell is one viewport tall and the screen scrolls inside it.** The nav is drawn as a persistent element in every mode, and it only *is* one if nothing outside the screen scrolls: the shell is a fixed `100svh` grid whose main area is the scroll container, so the 3-tab bar stays in the thumb zone on the app's longest list, the rail and sidebar keep their pinned foot (`ACCOUNT` above the sync marker) at the bottom of the screen rather than the bottom of the document, and the phone header — which carries the sync line and the only route to Account below Split — stays with them. Sized by `min-height` all three scrolled away, which is what a list longer than the viewport had been doing since the shell was built. One deliberate exception: at font sizes large enough that the header and the bar would leave the screen under half the viewport, the shell overflows and the document scrolls again, bar included — a 34px reading area is worse than an unpinned bar. [`frontend-design.md` §3.1](../frontend-design.md) has the mechanism and its consequences.

## Status Grammar (hybrid — decided)
Never color alone: every state = **shape + fill-level + label**.
- **Packing progress = one circle, fill = state:** ○ empty stroke `#97A08C` NOT PACKED → ◐ left-half filled `#D3A344` STAGED → ● filled `#7BB389` with dark check PACKED.
- **▲ triangle = separate attention class** (`#D98263`): missing, lost, disagreement. Never used for progress.
- **RETIRED** = strikethrough, muted `#6A7161`.
- Status pill: 1.5px colored border, radius 999, tinted bg when non-empty, 12px icon + mono 9.5/600 label, padding 11px 14px — sits at the row's right edge (thumb side).
- **Journey rail** (container headers): chips for ⌂ HOME ✓ → STAGING ✓ → CAR ● → PACKED; past = bordered muted + ✓, current = inverted (bg `#E8E5D5`, text `#151A15`, ●), future = dashed border `#47523F`, text `#5E6857`.
- **Disagreement marker:** mono amber `#D3A344` line, e.g. `▲ IN CAR · 3 INSIDE NOT PACKED`.
- **Per-person piece circles:** initial = person, fill = that piece's status (filled sage = packed, half amber + amber border = staged, bordered `#47523F` = not packed). Sized by the density of the band it sits in, never by the screen (the scale — §5d K): 22 chrome clusters (cards/headers) · 24 dense display rows (TABLE-44: builder row, read pane — holds at the read pane's 44px density, S8) · 28 group headers · 30 roster rows (48px picker/People rows) · 34 packing rows (S9). In the **builder** circles mean inclusion, not status: all bordered; dashed border + dim = excluded. The cluster + `×N` is **one control** — circles are never individual tap targets (§5d B); past four people the cluster paints exceptions first, then `+N` (§5d E).
- **Two worlds:** ⌂ HOME (muted `#97A08C`) vs ▸ ON TRIP (amber `#E2A65B`), everywhere. Depot never shows packing status; a trip row keeps its home path visible but muted.

## Voice: strict ledger
Terse, factual, numeric; mono for counts; sentence case for UI text; CAPS mono for labels. No exclamation marks, no cheerleading, no "oops".
Write: `3 left.` · `Packed · 14:32.` · `Offline. Saved on device.` · `Retired 2024. Kept in ledger.` · `No matches. 2 filters active.`
Never: "Almost there!", "Great job 🎉", "Say goodbye to this item?".

## Vocabulary guards
- **Piece** (capitalised) = one participant's copy of per-person gear on a trip — the only sense. Depot units of counted gear have **no identity, no name, no condition**; gear whose units genuinely differ is separate Single gear.
- **open** = the unresolved unpack state, everywhere (count line, filter pill, status pill, close card); never "out", which misreads as still away.
- **Unaccounted** = the read-back of `lost` (MVP): `▲ LAST SEEN: <trip>` + `RESOLVE`, identical in Find, Gear detail, and the Depot WHEREABOUTS column. `lost` writes nothing to the depot and keeps the gear's home slot.
- **Whereabouts words (ruled — Components §11):** the glyph names the **world** (`⌂` home, muted / `▸` on trip, amber / `▲` unaccounted, attention); the word after it names the **residence** where the surface answers residence (a path, or `LOOSE` for "lives nowhere" — the glossary term, written `⌂ LOOSE`), and the bare world (`HOME`, `ON TRIP`) where it only answers world. `HOME` never names a residence; `LOOSE` never stands alone as a world. One screen may correctly show both (Find: `⌂ HOME` chip beside a `⌂ LOOSE` line) — two questions, two words.
- **Tag** = flat, lowercase, `#` is drawn never stored; wire constraint (proposed for sync-protocol §4): lowercase `[a-z0-9-]`, 1–40 chars. No Tag entity, no rename — the pickers (§4a) are the only spelling defence. Trip-only gear is never tagged. `KIND` in UI always means the glossary Kind (`SINGLE · PER-PERSON · COUNTED`), never the containment trait (`ITEM`/`CONTAINER` — meta-line words only). "Slice" stays out of UI labels — the glossary has only "Saved slice" (Later); the phone control is the readout + `Sort and group` sheet.

## Auth vocabulary & rules
Use these words exactly; never "account" (except the tab name), "user", "profile", "log in", "admin", or "registration".
- **Household** — the people, depot and trips that belong together; the privacy boundary. **Person** — a household member who may join trips; most never sign in. **Quartermaster** — a Person who manages the Depot and outfits Trips; all identical in power, no hierarchy. **Login** — a Person's ability to sign in; one Person holds at most one. **Passkey** — a credential proving a Login; a Login may hold several or none. **Device** — one signed-in browser installation; listed and revocable. **Invite** — a single-use, short-lived link: a **join invite** creates a Login for a Person; a **device link** signs an existing Login in on another Device. **Maintainer** — whoever runs the server; not a role in the product.
- Verbs: *sign in / sign out* (never "log in/out"), *join*, *invite*, *revoke*, *add a passkey*, *issue a device link*.
- Rules the UI must keep visible: no passwords or email anywhere (foerier sends no mail) · no usernames — one button · devices without passkeys are equals · all Quartermasters equal · offline work is never lost to auth, and every session-ending screen says so · invites always state single-use + remaining time · opening a link does nothing until confirmed · auth exists on exactly two surfaces (signed-out shell, Account) and never interrupts Depot, Trips or Find.

## Interactions & Behavior
- Tap a status pill → next state (○ → ◐ → ● → ○). Long-press a per-person cluster → apply to all people. UNDO appears after every change.
- Moving a container moves its contents in one action; containment is a path (`ATTIC ▸ SHELF ▸ CRATE B`), one level shown at a time.
- Adding to a trip lists it; nothing moves until pack-out. Consumed decrements depot quantity quietly; Lost writes nothing to the depot, keeps the home slot, and stays searchable; trip-only entries are cleared at close. Marking `back` mid-unpack returns whereabouts home immediately.
- Over-claim check at activation only (adding to an active trip · starting pack-out · reopening): **warns and allows** — ▲ + attention colour + settle routes; never a block, never a filled red button, never discarded work. Drafts overlap freely.
- Reopening a closed trip restores its Unpack exactly as it stood (closing clears nothing). Changing an outcome away from `consumed` **offers** to restore the owned-count and waits for confirmation — a hand-corrected count is never rewritten silently.
- Phase model: `DRAFT → PACK-OUT → ON TRIP → UNPACK → CLOSED` — set by a quartermaster, never by dates or counts, movable in **both directions**. The phase chip opens SET PHASE; the CTA names the current phase verb but is only a suggestion. Day count runs from the phase change.
- Offline is normal, never a blocking dialog: sync state is one quiet header line (sage dot SYNCED / amber dot OFFLINE). Search, edit, pack fully on-device.
- Desktop keyboard: `↑↓` row, `space` select, `/` focus search, `enter` open/add, plus builder shortcuts above.
- Hover states (desktop): rows/nav items `background:#1F2620`. Focus: 2px amber ring.
- **Auth:** one button → OS passkey sheet (incl. the browser's cross-device QR — external, recreate nothing). Failure returns to idle with `▲ Sign-in did not complete. Nothing changed.` Invites: join 7 days, device link 1 hour, both single-use; opening a link changes nothing until confirmed; REVOKE kills the link only. Remote sign-out reaches a device at its next sync; sign-out-this-device clears local data and warns with the exact unsynced count. Session loss is discovered by the sync client, never interrupts a task, and queued work flushes on the next sign-in.

## State Management
- Entities: Gear (kind item/container, owner shared|person, owned-count, home path, tags — **no per-unit identity, no condition, no purchase year**), Trip (optional dates, people incl. non-packing participants, phase — set by hand, both directions — gear list with per-person allocation, trip-only entries), LedgerEvent (append-only: packed/listed/moved/back/lost/consumed/retired, timestamp, actor — **LATER**, story 33, derived from the change log).
- Split whereabouts: a counted gear's quantity splits across worlds (×1 home, ×1 on trip — both shown). Per-person **Pieces** exist only in trip contexts.
- Local-first store + on-device search index; background sync; last-synced timestamp surfaced in sidebar/header. First sync on a new device is a blocking, determinate fold of the household's op log (ops folded / ops known) with the bootstrap cursor persisted per page — it resumes, never restarts (sync-protocol §7).
- Close gating: `open === 0` (every piece resolved to back/consumed/lost) enables Close. `back` writes home immediately, mid-unpack. Closing retains the packing arrangement without effect, so a closed trip can reopen to Unpack as it stood; outcome edits away from `consumed` offer (never force) an owned-count restore.
- Auth entities: Household (privacy boundary — nothing crosses it), Person (holds at most one Login), Login (holds Passkeys and Devices; all Logins have identical powers — no roles in data), Passkey (coarse label, added, last-used), Device (coarse label, last-seen, token), Invite (kind join|device-link, single-use, expiry, revocable). The offline queue survives a revoked token; it flushes after the next successful sign-in — only an explicit "sign out this device" clears it.
