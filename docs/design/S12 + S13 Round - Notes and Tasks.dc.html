I1 — ORDER: BAND · TASKS · NOTES · GEAR LISTSHELLDRAWN
Document order at every width: screen band → header block → EDIT → over-claim band → TASKS → NOTES → GEAR LIST band + groups → the phone's add affordances. Both panels sit between the band and the list, and the band stays first: it is the one thing on the screen that must be settled. The two panels are bounded — a checklist and a handful of jottings — and the gear list is the only thing that grows past a viewport, so a panel below fifty-eight rows is a dead end on the phone, the very shape EDIT LIST › was added to close. TASKS before NOTES: a pre-trip list is read at Draft and Pack-out, when the gear list is being built beneath it; notes are written from On trip on, when the list is settled.
I2 — EACH PANEL ALONE TAKES THE SAME SLOTSHELLDRAWN
S12 and S13 may land in either order, so each panel is drawn without the other (03). A missing panel draws nothing — no band, no placeholder, no gap — and the one that exists sits exactly where it sits when both do. Whichever ships first is correct alone, and the second slots in without moving anything above or below it. Container arithmetic (I7) is the only thing that changes.
I3 — BANDS IN THE GEAR LIST IDIOM; THE NOUNSSHELLDRAWN
Each panel opens with the GEAR LIST band's anatomy: mono CAPS label left, count right, trailing link where one exists. Nouns, under the standing rule (ENTRIES counts the list, PIECES the things, GEAR the depot): the TASKS band reads 3/7 TICKED — a fraction in F4's 48/61 grammar, legal at 0/7 because a fraction is not a zero segment, absent at N = 0 (G3). The NOTES band reads 4 NOTES, absent at zero. F5's card reads 3 NOTES · 2 TO REVIEW, the second segment absent at zero. No circle glyph on either — ● is packing.
I4 — THE SPLIT DOES NOT REACH THE PANELSSHELLRULED
From Split up the trip screen reads and the builder edits (S7) because the builder needs a second pane — the depot picker. Neither panel has a second pane: a task is one row typed in place, a note is one screen. So capture exists at every width, on the trip screen itself. The story's own case decides it: a note is captured mid-trip on a phone and typed on a laptop after; capture that existed only below Split would strand the laptop.
I5 — THE TRIPS CARD GAINS NO SIXTH LINESHELLDECLINED
S9a records the card at five elements, full. A 3/7 TASKS line or a notes count would be a sixth, and neither earns it: the NEXT line already states the per-phase obligation, and the progress slot is the pack-out arithmetic on Active cards only. Tasks and notes are read on the trip screen, one tap in. Ruled for both branches so neither reaches for it.
I6 — NEITHER COLLAPSES; BOTH BANDS STAY IN EVERY STATESHELLRULED
A collapse adds a per-device state and hides the composer behind a tap; PERSON mode's all-done header is a precedent for a sixty-one-row list, not a seven-row one. Neither panel collapses. The bands stay in every state, empty included — a departure from the gear list, whose band goes empty because it carries doors (PACKING ›, UNPACK ›) that must not render on an empty list. The panels' bands carry a label and a composer or a link, both of which exist in every state.
I7 — STACKED BELOW 40REM, 2-UP FROM THERE — A CONTAINER QUERYSHELLDRAWN
What exists is decided once (I1); how it lays out is the panel row's own container: stacked, edge-to-edge, below a 40rem container; from there both panels 2-up (1fr 1fr, gap 24) as bordered cards with 12 between (A10, E6). A lone panel does not stretch across 808px of Desktop — it caps at the 560 column A10 gives F4 and F5, left-aligned. New frames at 540 draw the gutter token, 24 (E5), not the boards' 20.
I8 — S13'S COST, MEASURED: IT STAYSSHELLRULED
Seven tasks cost 7 × 48 + band + composer ≈ 420px above the gear list on the phone at Draft — a viewport. That is the honest number, and it is bounded: a checklist is short by nature, and the list's working screens are F4 and F5 behind their doors. Story 15 stays MVP. Because of I2 the shell does not change if it moves to Later: the tasks slot simply never fills, and nothing else on the screen knows.
I9 — THE COMPOSER IS A SCREEN, /TRIPS/:ID/NOTES12DRAWN
A picker must stack on it (I10), which is §3b's rule for a screen over a sheet — the same reason /trips/new is one. Band ‹ ALPS 2026; title Note; a multiline well focused on open (return is a newline — prose gets a review before it is posted, since it cannot be edited after); the ABOUT row; a pinned accent Post note, gated on non-blank text (whitespace is empty — the form-CTA gate, Add gear's). No counter, no cap: 16 KB is far past any jotting. After Post the screen returns to its caller — one note is not a sitting.
I10 — ABOUT THIS ENTRY: THE COMPOSER'S OWN ROW, NEVER A HOST ROWS12DRAWN
Where entry_id is set: the composer's ABOUT row, a 48px bordered row (Add gear's HOME row) opening a picker sheet in the Home picker's anatomy — The trip first with meta NOT ABOUT ONE ENTRY and ● NOW, then the gear list A→Z; selection closes, the scrim dismisses. No capture on a host row: F4's and F5's rows already carry their two targets (A2), builder rows carry a stepper and ✕, and the read rows from Split up are reads. How it reads: on the note alone, as a meta segment in the LABEL: value grammar — ABOUT: CAMP CHAIR — never on the Entry's row, whose grammar is settled. A removed Entry keeps reading ABOUT: CAMP CHAIR; the note was about it.
I11 — ANATOMY: TEXT · TIME · REFERENCE; OLDEST FIRST; NO BYLINES12DRAWN
Text 15/22 ink, rendered whole. Meta mono 11 muted: 2026-08-16 21:07 · ABOUT: GAS CANISTER 450 — the time is the op envelope's clock, a fact every reader holds, rendered in the reader's local time by the one formatter (§12's shape, no zone). No byline: the envelope carries a Device, not a Person, and copy blocked on a field is omitted, never faked. Oldest first: a ledger appends, and the F5 review and the S14 copy read the same order; newest-first is a feed's convention.
I12 — NO EDIT, NO DELETE — THE PRECEDENT HOLDS, UNSAIDS12RULED
A posted Note is permanent text, as S7's trip-only Entry is un-renameable, and for the same structural reason. A typo is likelier on prose than on a gear row, and the answer is the same: post another. The UI states nothing — a missing op is a fact for the docs, and the sync protocol already files it as a requirements gap for the requirements process. The composer's one defence is I9's: the text is on screen before Post note, not committed on return.
I13 — ABSENT KEPT = UNREVIEWED; ONE SELECTOR, THREE ANSWERSS12RULED
noteKeptOf answers true | false | undefined — kindOf's shape: a register with no default still has exactly one function, and no reader invents a value. What each surface draws: an unreviewed note is plain (the absence is stated once, as F5's 2 TO REVIEW); kept appends · KEPT to the meta; discarded takes the RETIRED grammar — strikethrough, muted — and appends · DISCARDED. Stated here for S14 to read: a Note not discarded is copied. The discard is the act; the review is the chance to make it.
I14 — THE REVIEW: A CARD ABOVE THE CLOSE CARDS12DRAWN
In F5's anatomy the notes review is a surface card after the groups and directly above the close card, so the close card stays the list's last card (F11). Header NOTES · 3 NOTES · 2 TO REVIEW (the second segment in ink, as 6 OPEN is) · trailing + NOTE. Each row: text, meta, then the settle-routes grammar — KEEP · DISCARD in accent, gap 14. A reviewed row shows its state in the meta and the other route only: tapping the current value writes nothing (§2.3), and a discard is reversed by KEEP — the tag-chip rule, one tap. Outside the mode control and the ○ OPEN filter; unaffected by either.
I15 — NOTES DO NOT JOIN THE GATES12DECLINED
Invariant 18 states the gate exactly — every Entry and Piece resolved, open = 0, no override — and its purpose is the Depot not drifting. A Note writes nothing to the Depot, so an unreviewed Note is not a false statement about it, and putting one behind the button would make Close trip — 6 open count two registers under one word. The summary line, the button and both hints are unchanged. The story's at the Unpack pass I review is satisfied anyway: the card sits on the path to Close at every width and states its own count, and skipping it loses nothing a discard would have removed (I13).
I16 — DISCARDED NOTES NEVER VANISHS12RULED
The register survives the discard, so the note does: RETIRED grammar on every surface, the closed Trip included — Retired 2024. Kept in ledger. is the voice. It counts in N NOTES. S14 does not copy it. The reversal is I14's KEEP.
I17 — A CLOSED TRIP: POST, KEEP AND DISCARD STAY LIVES12RULED
§3.8's test, run: which invariant closes the write? None. Invariant 19 and G6 freeze outcomes; invariant 14 keeps notes as history without freezing them; invariant 16 says no phase locks anything; story 12 says mid-trip or after. So the panel is identical on a closed Trip, and F5's notes card keeps its routes while every pill around it is a record — name the invariant, not the phase: F5's record prop is invariant 19's and does not reach the card. Checked for a hidden conflict: none; a warmer-gloves note in November is the story's own example.

I22 — THE WHOLE ROW TICKS; THE SQUARE IS THE READOUTS13DRAWN
A task has one track, so one target: the row (list-row rule — the whole row is the tap target). The square at the right edge (thumb side, the pill's slot) states the value and is not a second target. Rows are ≥48 so the hit floor is met by the row itself — no ::after, nothing to clamp. One op per tap, both directions.
I23 — THE GLYPH: A SQUARE, IN INKS13DRAWN
○ ◐ ● is packing progress and ▲ is attention; reusing either is S5's trap. A ticked Task is a square — 18px, radius 3 (the badge radius), 1.5px #47523F — with a ✓ in ink inside; the row's text goes muted. Unticked is the empty square with the text in ink. Shape + fill + label: square, empty or checked, and the band's 3/7 TICKED. No status colour at all, so the parchment theme has nothing to collapse.
I24 — INSERTION ORDER; TICKED ROWS DO NOT SINKS13RULED
A8's argument, verbatim: sorting by state moves rows under the thumb as they are tapped. Deliberate, and stated so nobody adds it: a ticked task stays where it was written.
I25 — LIVE AT EVERY PHASE, CLOSED INCLUDEDS13RULED
Same test as I17. Pre-trip names when a task is for, not when its register may be written; invariant 16 governs, no invariant closes it, and a task ticked after the fact — or added on a closed Trip for the next one — is a correction of the record. The panel's anatomy never changes with phase.
I26 — THE READOUT: 3/7 TICKEDS13DRAWN
On the band, I3's fraction. TICKED is the glossary's word (ticked off as done) and the register's. No bar — F4's bar measures sixty-one Pieces; seven rows are their own bar.

A composer on screen is the empty state. 0 TASKS. is not written because the list's end row is on screen whether the list is empty or not, and a count above it would state what the row already shows. The band stays (I6), count absent (G3).
