DECISIONS ON THIS SCREEN
The whereabouts card stacks both worlds — home slot stays visible while a unit is out, per principle 3. Counted quantities split by whereabouts (×1 there, ×1 out — both true) and carry no per-unit identity: gear whose units genuinely differ is recorded as separate Single gear. Condition and purchase year are recorded nowhere — condition is maintenance territory (story 17, Later) and would attach to the gear, never to units. Piece (capitalised) stays reserved for one participant's copy of per-person gear on a trip; it never names a depot unit. The ledger group (story 33, derived from the change log) is drawn final and tagged LATER. Retire is a text action, never a red button — it keeps the record. Tag chips are the settled chip: lowercase mono 10.5, 32px, bordered — the trailing + tag ghost is the one edit affordance on this read screen and opens the picker (§01B); ✕ lives inside the picker, not on the chips. A gear with no tags shows the lone + tag ghost. Removing a tag confirms nothing — it is one op, instantly reversible by re-applying.

THE VOCABULARY IS THE PICKER
There is no Tag entity — the list is derived from whatever is currently applied, and there is no rename, ever (settled). So the moment of typing is the only defence against #Cooking beside #cooking: existing tags are offered first, with counts, before creating is possible; + CREATE is a visibly distinct row; input is normalised — lowercased as typed, spaces become one hyphen, charset a–z 0–9 – — and the # is drawn by chips, never stored, so ##winter is unreachable.
That normalisation is the op payload. PROPOSED for docs/sync-protocol.md §4, whose {tag} row is currently untyped: lowercase, [a-z0-9-], 1–40 chars, stored without #. The protocol doc records it; a wire format that lives only on this board is not a contract.
RULES THAT TRAVEL WITH THE CHIP
Trip-only gear is never tagged (glossary, story 13, invariant 9) — neither picker ever mounts on it; the rule is stated now because the trip-side screens reuse this exact chip and picker from S7 on. The Depot table's TAGS column stays plain mono text that ellipsis-truncates — deliberate: at 44px density chips would dominate the row; the full set lives on gear detail, one click away. Removal never confirms — cheap and instantly reversible.

DECISIONS ON THIS SCREEN
One active trip gets the only card with a CTA. Drafts are dashed outlines — lists in progress, not commitments. Closed trips are ledger rows: date, piece count, losses. A lost piece stays visible at trip level forever; that is the ledger keeping score. Every closed row carries REOPEN — closing clears nothing, so a trip closed too early, or one whose lost gear turns up months later, returns to Unpack exactly as it stood (02B).
PHASE MODEL
DRAFT → PACK-OUT → ON TRIP → UNPACK → CLOSED. Phases are set by a quartermaster, never by dates or counts, and move in both directions — “we had left” until the duffel turns out to be still in the hall. The chip carries the day count; the CTA names the current phase verb but is a suggestion, not the only route: tapping the phase chip opens SET PHASE.

OVER-CLAIM — WARNS AND ALLOWS
Two active trips cannot both take the same gear: Single gear is exclusive, counted bring-counts cannot sum past the owned-count, per-person gear is per participant. The check fires at three moments — adding gear to an active trip’s list, starting pack-out on a draft, reopening a closed trip — and always offers the settle route: remove (or reduce) the entry on one trip. Attention colour and ▲ only; never a filled red button, never a block, never discarded work. Drafts overlap freely — the warning belongs to activation, not to planning.
REOPEN — DELIBERATE, NOT ALARMING
Same register as deleting a trip (a deliberate, confirmed act) but nothing was thrown away, so the primary stays accent, not attention. Reopen exists for a trip closed too early and for lost gear that turns up months later — resolving the entry then hands the gear home, as during any unpack. If reopening would over-claim against another active trip, the same ▲ block appears in this sheet.

DECISIONS ON THIS SCREEN
Grouped by home destination, not by container — you walk the house once and empty as you go. Four verbs: BACK, OPEN, CONSUMED, LOST — one word for the unresolved state, matching the count line and the close card; nothing here says “out”, which misreads as still away. Marking BACK hands the gear home there and then, before the trip closes. Consumed is not lost; it reduces the depot count without an alarm. Close is gated on open = 0 and the button says why it is waiting.
