DECISIONS ON THIS SCREEN
The whereabouts card stacks both worlds — home slot stays visible while a unit is out, per principle 3. Counted quantities split by whereabouts (×1 there, ×1 out — both true) and carry no per-unit identity: gear whose units genuinely differ is recorded as separate Single gear. Condition and purchase year are recorded nowhere — condition is maintenance territory (story 17, Later) and would attach to the gear, never to units. Piece (capitalised) stays reserved for one participant's copy of per-person gear on a trip; it never names a depot unit. The ledger group (story 33, derived from the change log) is drawn final and tagged LATER. Retire is a text action, never a red button — it keeps the record. Tag chips are the settled chip: lowercase mono 10.5, 32px, bordered — the trailing + tag ghost is the one edit affordance on this read screen and opens the picker (§01B); ✕ lives inside the picker, not on the chips. There is no Tag entity — the list is derived from whatever is currently applied, and there is no rename, ever (settled). THE INTERIM RULE — S6
A board’s CTA copy lands on the slice that builds its destination: BUILD LIST › arrives with the builder, Continue pack-out with the packing view. Until then no card carries a button or verb link — the shipped OPEN › is retired: it spent the system’s strongest element on its flattest verb and taught the accent button to mean nothing. In the progress slot, a per-phase NEXT line — a permanent obligation, not a stand-in: it survives the progress line and sits above it (full-weight card below). Five strings, two redrawn: PACK IT → PACK THE LIST; MARK UNPACK WHEN YOU ARE BACK → SET UNPACK WHEN BACK — it names the actual control. DATES — THE OS OWNS THE INPUT (S6)
Start and End are native date inputs — an external surface, the passkey-sheet rule: recreate nothing; the boards draw dates only as output. Both optional; both empty writes nothing at all. There is no end-before-start guard — two devices may legitimately write the two ends concurrently, and a guard would have to discard one of two valid writes. A reversed range is reported in the ledger’s own idiom, never prevented:
SEP 02 → AUG 14 · ▲ ENDS BEFORE IT STARTS
— and the day count is suppressed while reversed (it would be false). A stored date that is not YYYY-MM-DD renders an empty input while the value survives; EDIT states it beside the field, so the field never silently looks cleared:
▲ STORED AS “aug sometime” — PICKING A DATE REPLACES IT
ONE COMMIT MODEL — S6, REDRAWN
The shipped screen had two: typed fields on Save/Cancel, a participant tap at once, patched by a disclosure line. Redrawn: participants leave EDIT and live on the resting screen — gear detail’s tag-chip pattern, the one edit affordance on a read surface. Circles plus a dashed + ghost open the picker; writes land at once; removal never confirms (cheap, instantly reversible — the tag picker’s rule). EDIT now covers name and dates only, one commit model, and the disclosure line is deleted. The picker is rows, not circles — rows are what pickers are made of everywhere here; circles are display. Multi-select membership is marked PARTICIPANT ✓, the builder’s IN LIST ✓ grammar; ● NOW stays the single-select word. + NEW PERSON records a Person and selects them at once — the home picker’s + New place rule.
UNRECOGNISED PHASE · THE ● NOW TAP (S6)
An older build folding a newer phase draws it verbatim, lowercase, in a quiet bordered chip — no amber (an old build must never over-state that a trip is Active), and no ▲: the data is right, the build is old, and there is nothing for the household to resolve — the attention class is for things that want an action. It files under the planned band, gets no NEXT line, and SET PHASE marks no row: ● NOW — portaging stands above five tappable rows, so no trip is ever stranded in a phase this build cannot leave. Tapping the ● NOW row writes nothing and closes — a redundant write would reset the chip’s DAY count to a visible lie. The row stays undimmed: dim means future or disabled, and NOW is neither — it is satisfied.
SMALL TREATMENTS + LIST STATES (S6)
Blessed as shipped: the draft chip stays quiet mono, never amber — amber is the trip world and a draft is not in it. The SET PHASE sheet titles SET PHASE alone — the chip that opened it is the trip’s own, and every sheet carries a short label (excerpt in 02 updated). TRIPS 0 in the desktop sidebar — the count is the size of the list the row opens, exactly as DEPOT 0. New trip is a screen, not a sheet: the participants picker must stack on it, and it follows Add gear’s shape — name first (the only required input, focused), dates, participants, thumb-zone CTA gated on name; at desk widths Enter creates. Decided now: the middle band is named PLANNED against the day it needs a header — it holds drafts and unrecognised phases, so DRAFTS would misname it; only CLOSED draws a header today, as the board had it. Two Active trips render as N identical cards, no primary-trip treatment — their interaction is the over-claim surface’s job (02B). The Trips list gains the Depot’s 56px FAB as + NEW’s drawn control (F3 had the step, no frame).

NAME IS THE ONLY REQUIRED INPUT here and Add gear’s matching ledger line were drawn centred on every phone frame and inline on Add gear — split 900 — never a contradiction: below Split the primary is full-width and pinned to the thumb zone, and the line centres beneath it; from Split up the form is a pane, the primary is an inline 40px button, and the line sits beside it in the same row. OVER-CLAIM — WARNS AND ALLOWS
Two active trips cannot both take the same gear: Single gear is exclusive, counted bring-counts cannot sum past the owned-count, per-person gear is per participant. The check fires at three moments — adding gear to an active trip’s list, starting pack-out on a draft, reopening a closed trip — and always offers the settle route: remove (or reduce) the entry on one trip. Attention colour and ▲ only; never a filled red button, never a block, never discarded work. Drafts overlap freely — the warning belongs to activation, not to planning. S7 adds the fourth condition, which is not a moment: a clash can arrive through sync while nobody is doing anything, so the three moments’ sheets are previews of a standing surface — the over-claim band on /trips/:id (02C), rendered whenever the fold says conflict, gone when somebody settles it, never dismissible.
REOPEN — DELIBERATE, NOT ALARMING
Same register as deleting a trip (a deliberate, confirmed act) but nothing was thrown away, so the primary stays accent, not attention. Reopen exists for a trip closed too early and for lost gear that turns up months later — resolving the entry then hands the gear home, as during any unpack. If reopening would over-claim against another active trip, the same ▲ block appears in this sheet. S6 ships the confirm as title + body only — the mono blocks are conditional on Entries and outcomes and return with them; they are information, not weight, and the register is the confirm itself. The body is parameterised: “It returns to {phase} exactly as it stood.” — SET PHASE offers all four rows out of CLOSED, and refusing them would contradict its own ANY ROW TAPPABLE; the closed row’s REOPEN link targets Unpack, where this sheet’s sentence renders verbatim.
